# Performance and validation

Windows, Godot 4.7.2 Compatibility, OpenGL 3.3, GTX 1050 Ti, 1280x720 window. Same starting camera and room lighting. FPS cap and VSync disabled for measurement only; normal play uses a 60 FPS cap. Fresh process, warm-up before each mode, frame intervals measured with Time.get_ticks_usec. Baseline sampled 180 frames per mode; final sampled 240. These are short desktop measurements, not CPU/GPU utilization or a phone/browser benchmark.

| Mode | Draw calls | Median frame ms | p95 ms | Godot static memory MB | Reported video memory MB |
| --- | ---: | ---: | ---: | ---: | ---: |
| Before: original | 874 | 7.040 | 8.552 | 76.65 | 40.27 |
| Before: half-resolution pixelation | 874 | 6.393 | 7.633 | 76.65 | 34.74 |
| After: Original | 48 | 2.587 | 2.945 | 75.18 | 43.25 |
| After: Mild PSX | 48 | 2.091 | 2.390 | 75.19 | 37.72 |
| After: Strong PSX | 48 | 2.080 | 2.415 | 75.19 | 36.32 |
| After: Eco | 27 | 1.945 | 2.243 | 75.19 | 37.70 |

The main gain is static room batching: 613 surfaces become 33 material batches. With the HUD, observed draw calls fell about 94.5%. Half-resolution plus the new mild effects took about 67% less median frame time than the old pixelation-only demo on this PC. Performance will change with camera position, hardware and scene size.

Memory is a tradeoff: Godot's reported static allocation dropped slightly, while reported video memory increased about 3 MB at the same resolution because batched room geometry is stored together instead of reusing every original mesh instance. These counters are not the process's full RAM or the driver's total VRAM allocation. We do not claim universal RAM/GPU-memory savings.

Dithering samples the existing viewport texture; no extra scene render or screen copy. Wobble runs in the vertex shader and skips shadows. Converted materials share textures and are cached. No per-frame mesh scan. Eco disables the two shadow casters and wobble. The normal 60 FPS cap avoids spending the measured spare capacity drawing hundreds of unnecessary frames.

Visual validation sampled every fourth pixel: 23 of 57,600 samples changed beyond a 0.01 color threshold between the source room and the first baked room. Collider counts matched. Actual screenshots were inspected. The regression suite also checks stable mouse sensitivity, movement, lights, resolution switching, UI input blocking, effect visibility, comparison restoration, focus loss and unsupported-material preservation.

Source and final raw data: performance-before.json and performance-fresh.json. The performance.json generated by the extended validation run includes additional comparison-test allocations and should not be used as the fresh-process memory baseline.

Not tested: an actual phone, itch/Web export, Forward+ or Mobile renderer. First-run shader compilation and loading can still cause a startup hitch. The baked demo room is static; keep original source assets for animation/editing.
